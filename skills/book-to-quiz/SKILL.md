# Book-to-Quiz（知识书 → 习题集）

## When to Use

- User provides a knowledge book / document (PDF, EPUB, MD, HTML, TXT) and asks to convert it into an exercise set (习题集) for self-testing, placed in their Obsidian vault.
- "把这本书转成习题集" / "这本书每章出几道题" / "make an exercise set from this book".

Design decisions below are **user-mandated** (locked with Maxim 2026-09): do not silently extend or relax them.

## 设计原则（硬性规则，不可违背）

1. **只出回忆式（产出式）题型**：概念题（简答）、举例题、推导题、应用题。禁止选择、填空、判断、找错（见下）。
2. **不呈现错误表述**：任何题干的材料都不得包含错误命题/错误选项/待找的错。理由：呈现错误表述会强化错误认知。
3. **举例题允许引用书中实例**（有印象即可），不强制创造书外新例。
4. **应用题必须三级结构**：判断→套用→论证（见题型规格）。
5. **每题必带**：难度（☆基础 / ☆☆进阶 / ☆☆☆综合）+ 答案与解析 + 出处（章节/页码）。
6. **出处缺失不得编造**：解析中引用书内位置必须来自实际抽取的文本；找不到就标 `出处：TBD（待核对）`，不虚构页码。
7. **覆盖驱动（无配额）**：以**结构化知识点**为单元（术语、命名框架、决策规则、书内实例——书中明确给出定义/演示/强调的单元），每个知识点必映射 ≥1 道题，覆盖度目标 100%（穷尽枚举知识点，但每点一题、呈现精炼——密度优于堆砌，参考 book-to-skill 质量规则）；题型由知识点性质决定（见"题型选择映射"），不按固定配额硬凑。
8. **答案分离**：默认每题后跟折叠 callout（`> [!answer]-`）；另可一键导出独立答案册（`scripts/export_answer_book.py`），便于打印。

## 禁用的题型

| 禁用 | 原因 |
|------|------|
| 选择题（单选/多选） | 再认式；含干扰项即呈现错误表述 |
| 填空题 | 再认/回忆碎片，测不出理解 |
| 判断题 | 错误命题强化错误认知 |
| 找错题 / spot-the-error | 同上，题干必含错误表述 |
| 综合论述题（跨章） | 用户明确不要（2026-09） |

## 题型规格

**题型选择映射**（出题量由覆盖矩阵决定，无固定配额；每个知识点按性质选最贴合的题型。"提取类别"列源自 book-to-skill 的章节提取模板）：

| 提取类别（book-to-skill） | 知识点性质 | 题型 |
|---|---|---|
| Key Concepts / Glossary | 书中给出定义的术语、明确对比的概念对 | 概念题（简答，含辨析） |
| Worked Example / 书内实例 | 书内实例/示例（回忆实例并说明其体现的要点） | 举例题 |
| 定理/结论（可推导） | 可推导的定理、结论 | 推导题 |
| Frameworks（When/How）+ Mental Models | 命名框架、决策规则、方法/流程 | 应用题（识别+套用） |
| Reference Tables / 决策规则 / 阈值 / tells | 判断力层：对比矩阵、阈值与默认值、启发式 | 应用题（图/数据 或 场景） |
| Key Takeaways / Connects To | 跨点洞见、章间关系 | 概念题（进阶）或并入相关题 |
| Anti-patterns | ⛔ 不提取为题目材料 | 跳过或转正为"正确做法"（设计原则 2） |

### 1. 概念题（简答）

考"能否用自己的话讲清定义、范围、易混区别"。形式：开放式简答，不提供选项。

- 基础版："什么是 X？用一两句话给出定义。"
- 辨析版："X 和 Y 有什么区别？各自适用的条件？"（X/Y 来自书中明确对比过的概念）

### 2. 举例题

考"书中实例 → 概念"的对应。允许引用书中实例，有印象即可；解析里说明"这个例子为什么体现该概念"。

- 标准版："书中用哪个例子说明 X？它体现了 X 的哪些要点？"
- 进阶版（可选，☆☆☆）："举一个书中没有的 X 的例子，并说明为什么成立。"（用户不强制，仅在概念确实适合时出）

### 3. 推导题

考"从原理/定义推出结论"。要求展示推导过程，禁止跳步；解析给出完整推导链并标注每步依据（书中定理/定义）。

- 形式："从 X 的定义出发，推导 Y 成立。" / "证明/推导：…"
- 无推导内容的章节（纯概念/叙事）自然没有推导题，覆盖矩阵里就没有这类知识点，题量随知识点走。

### 4. 应用题

**三级作答结构**（每道题都要逼用户走完三段）：
1. **判断**：该情境该用书里哪个框架/方法？（考识别）
2. **套用**：把情境数据代入框架，得出具体结果（考执行）
3. **论证**：为什么这么判断？前提/边界条件是什么？条件变了结果怎么变？（考元认知）

**按题干载体分三类**（按书型选，不必每章三类都有）：
- **A. 图/数据驱动**：题干给图表/数字/结构，让用户分析（如：给一段 K 线标中枢、判级别、定买卖点）。适合 technical / 结构型书。
- **B. 场景驱动**：纯文字情境让用户决策（如：你的宿主换成 X，书中策略哪些步骤要调整？）。适合 text / 方法论型书。
- **C. 变式驱动**：把书中例题改一个参数/前提，问结果怎么变、为什么（测真懂机制 vs 背例子）。两种书型都适用。

**开放度标注**（每题标一个）：
- **封闭型**：结果唯一，答案册可直接判定对错。
- **半开放型**：多个可行解，答案册给**要点式参考答案 + 评分要点**（说对哪几个要点算过），不给唯一答案；解析里可加"常见错误"栏提醒易想当然的步骤——但常见错误只出现在答案册（用户做完后才看），**绝不出现在题干**。

## Workflow（按顺序执行）

### Step 0 — 确认输入、目标范围与书型

- 记录：书路径（PDF/EPUB/MD/HTML/TXT）、**目标范围**、书型。
- 目标范围三选一（后续所有步骤只在该范围内进行）：
  - **全书**
  - **指定章节**（按章节标题/编号定位）
  - **页码范围**（如 `PDF 120–145 页`；主要用于 PDF。EPUB 为流式布局无固定页码，用章节代替；MD/TXT/HTML 页码范围 → 行号范围或标题定位）
- 页码范围模式下：覆盖矩阵只含该范围内的知识点；出处引用**原书页码**（非切片内相对位置）。
- 问书型（影响应用题载体选择；推导题多少由可推导知识点数量自然决定，非配额）：
  - `technical`：有代码/表格/公式/图（编程书、学术书、缠论类结构书）→ 应用题多用 A 图/数据 + C 变式，可推导知识点多则推导题自然多。
  - `text`：散文为主（管理、叙事类）→ 应用题多用 B 场景，可推导知识点少则推导题自然少。
- 输出位置：默认建议 `🏠 Private/习题集/<书slug>/`（先按 obsidian skill 读 vault README 确认规则；展示计划时与用户确认最终路径，不擅自决定）。

### Step 1 — 抽取文本（按目标范围截取）

- **PDF 页码范围**（优先，poppler 已装时最快）：`pdftotext -f <起始页> -l <结束页> input.pdf - > slice.txt`；无 poppler 用 PyMuPDF：`python3 -c "import fitz; d=fitz.open('input.pdf'); [print(d[i].get_text()) for i in range(a-1,b)]" > slice.txt`（a/b 为起止页号）；都没有则用 pdf skill 抽全文后按页号截段。
- **PDF 指定章节/全书**：`read_file`（自动抽取文本层）；扫描件先用 `ocr-on-mac` / `ocr-and-documents`（扫描件按页 OCR，正好支持页码范围）。
- EPUB / DOCX / MD / TXT / HTML：`read_file` 或 `web-content-extraction`（HTML）；页码范围 → 章节标题定位或行号截取。
- 保存到临时工作目录：`/tmp/book_quiz_work/` 下 `full_text.txt` + `metadata.json`（来源、字数、章节边界、页码信息）。
- **确认抽到的就是这本书**（检查书名/第一章内容），再继续。
- **大书用 REPL 式探查，不整读**（借鉴 book-to-skill Step 2.6）：把 `full_text.txt` 当可查询语料库——`wc -w` 看规模、`grep -n -E '^(Chapter|CHAPTER|[0-9]+\s)'` 定位章节偏移、`sed -n '<start>,<end>p'` 拉单章、`grep -c '<概念>'` 验证某概念确实出现在书中。200 页书 ~75k tokens，整读会烧掉后面生成题目的预算；探查式访问让成本正比于输出。≤50k tokens 的书一次 `read_file` 即可。

### Step 2 — 章节结构与知识点提取（覆盖矩阵）

按 book-to-skill 的章节模板逐章提取**结构化知识点**：

1. **结构分析先行**（借鉴 book-to-skill Step 3）：读前 8,000 字符确定书名/作者/章节结构，再读目录映射全部章节——先有章节地图，后逐章提取。
2. 逐章提取（每类知识点记下**书中定义的关键词 + 出处**，如 `Ch3 §3.2 p.87`）：
   - **术语（Key Concepts）**：书中给出定义的重要术语
   - **命名框架（Frameworks）**：含 When to use / How，**保留作者精确命名**（"The 5 Whys" ≠ "多问几次为什么"）
   - **思维工具（Mental Models）**："Use X when Y" 式规则
   - **书内实例（Worked Example）**：作者完整走完的例子——举例题/变式应用题的核心素材
   - **定理/结论**：可推导的结论及其依据
   - **判断力层（cheatsheet 类）**：决策规则（"When X, do Y, because Z"）、阈值与默认值、对比矩阵、tells——最出应用题的材料
   - **章间关系（Connects To）**：概念在哪些章节深化/对比
   - **反模式（Anti-patterns）**：只提取"作者警告了什么场景"，生成时**转正**为"正确做法是什么"（设计原则 2：题干不得呈现错误表述）
3. 产出**覆盖矩阵**（行 = 知识点，非章节）：每行 = 知识点 | 提取类别 | 性质 | 出处 | 映射题型 | 映射题目。**知识点以书中结构为单元穷尽枚举**——每个术语、每个命名框架、每条决策规则、每个书内实例，无遗漏。题型按"题型选择映射"分配，量随知识点走。

### Step 3 — 展示生成计划，等待确认（强用户偏好）

多文件写入 vault 前**必须 Explain-first**：表格列出每个将创建的文件（路径 + 内容概要）+ 每章题型分配。用 `clarify`，不得在沉默中继续。（规则来源：obsidian skill "Multi-file writes: Explain first"）

### Step 4 — 生成题目（每章）

逐知识点出题：覆盖矩阵每行 → 至少一道题，题型按"题型选择映射"选择；一道题可合并覆盖多个紧密相关知识点（如辨析题覆盖一对易混概念），并在矩阵中标注。不为凑数加题、不为省事漏题。每题带难度、折叠答案、出处。生成时遵守：

- 题干只陈述书中成立的知识点；**不在题干中放任何错误陈述**。
- 应用题按三级结构写，并标注载体（A/B/C）与开放度（封闭/半开放）。
- 出处一律引用 Step 1 抽取文本中的真实位置，并用 REPL 探查核对（`grep` 确认概念确实出现在所标章节/小节），找不到标 `TBD（待核对）` 并汇报，不猜页码。

### Step 5 — 质量自检（每题 + 每章）

每题：
- [ ] 答案能从书中**唯一**推出？用 REPL 探查回原文核对出处与推导链？
- [ ] 题干无歧义（不会有两个合理解读）？
- [ ] 题干不含任何错误表述？
- [ ] 难度标注合理（☆☆☆ 需要多步/迁移才可解）？
- [ ] 概念题答案是"自己的话"可答（不是背定义）？

每章：
- [ ] 覆盖矩阵 100%：每个知识点都有映射题？未覆盖的补题后再继续。
- [ ] 应用题都有三级结构 + 载体 + 开放度标注？
- [ ] 出处无 TBD 遗留（有则明确列出待核对项给用户）？

### Step 6 — 写入 vault

- 新建文件：无需备份；但**写前重读**目标目录（用户可能已手动建过同名文件；CJK/emoji 文件名用 `terminal ls` 验证存在性，`search_files` glob 可能漏）。
- 若覆盖已有 `.md`：先 `cp` 备份为 `<name>.backup.md`，再改写。
- 文件结构（见"输出模板"）：`README.md`（索引+覆盖矩阵）+ 每章一个 `chNN.md` + （可选）`答案册.md`。
- 章文件内互相 wikilink；`README.md` 链到各章。

### Step 7 — 导出答案册 + 验证

- 运行 `scripts/export_answer_book.py <习题目录>` 生成 `答案册.md`（幂等：从习题文件重新生成，手改会被覆盖）。
- 验证：所有文件存在；wikilink 全部可解析（参考 obsidian-article-atomization 的 `scripts/verify_wikilinks.py` 思路）；`[!answer]-` 块在每道题后且成对；覆盖矩阵数字与实际题数一致。
- 报告：文件位置 + 题型统计 + 覆盖度 + 遗留 TBD。

## 输出模板

**Markdown 排版硬规则**（所有生成文件：README、各章 chNN.md、答案册）：

1. **标题与正文之间必须空一行**——`## 标题` 后空一行再接正文；题目标题（`### 1.1 …`）后空一行再接题干；列表、代码块、引用块（callout）与相邻段落之间同样留空行。
2. **正文中不使用分割线**（`---` / `***` / `___`）——层级靠标题与空行表达。（唯一例外：YAML frontmatter 的分隔符，那是语法必需）

```
🏠 Private/习题集/<书slug>/
├── README.md        # 书名、来源、书型、覆盖矩阵表、章索引（wikilink）
├── ch01.md          # 每章一个习题文件
├── ch02.md
└── 答案册.md        # 由脚本生成（可打印），勿手改
```

习题文件每题模板：

```markdown
### 1.1 概念题 · ☆☆ · Ch1 §1.2 p.15
**题干**：什么是 X？它与 Y 的区别是什么？

> [!answer]- 答案与解析（先自答，再展开）
> **答案**：…
> **解析**：…
```

应用题额外字段：

```markdown
### 1.5 应用题（载体：A 图/数据 · 开放度：封闭）· ☆☆☆ · Ch1 §1.4 p.32
**题干**：
1. **判断**：…
2. **套用**：…
3. **论证**：…

> [!answer]- 答案与解析
> **思路链**：…
> **答案要点**：…（半开放型：+ **评分要点**：说对哪几点算过）
> **常见错误**：…（仅答案册，不进题干）
```

## Pitfalls

1. **选择题/判断/找错是禁区**——即使用户没明说，也别"顺手加一道"；含错误表述的题干直接违背设计原则 2。
2. **应用题写成"回忆题"**——若题干只问"书里怎么做的"，那是概念题不是应用题；应用题必须有新情境（数据/场景/变式）需要用户判断+套用+论证。
3. **出处编造**——页码/章节号必须来自抽取文本，找不到标 TBD 并汇报，不猜。
4. **CJK/emoji 文件名 glob 漏检**——`search_files` 对 `*书slug*` 可能返回 0；存在性用 `terminal ls` 复核。
5. **不重读就改写**——用户可能在两次会话间手改 vault 文件；写前重读，备份后 patch。
6. **覆盖矩阵造假**——"覆盖度"必须回填实际题数核对，不能只写计划值。
7. **答案册手改丢失**——答案册由脚本生成，用户手改会被下次导出覆盖；如需保留修改，改习题文件里的 callout 再重新导出。
8. **用固定配额代替覆盖**——知识点少的章节硬凑题量，多的章节漏题。出题量唯一标准是覆盖矩阵：每个知识点 ≥1 题（题型按性质选）。

## 脚本

- `scripts/export_answer_book.py`：扫描习题目录的 `ch*.md`，抽取全部 `[!answer]-` callout，按章/题号重排生成 `答案册.md`。
  - 用法：`python3 scripts/export_answer_book.py <习题目录> [输出路径]`（默认输出到习题目录下 `答案册.md`）。
  - 幂等：每次从习题文件全量重建，无增量状态。
  - 只处理 `ch*.md`（跳过 `答案册.md` 自身）；答案 callout 须以 `> [!answer` 开头，延续行以 `>` 前缀，块与块之间有空行。

## Verification checklist

- [ ] 覆盖矩阵 100%：每个知识点映射 ≥1 题，题型由知识点性质决定（无固定配额）
- [ ] 无选择题/填空/判断/找错/综合论述
- [ ] 每题：难度 + 折叠答案 + 出处齐全；应用题含三级结构 + 载体 + 开放度
- [ ] 覆盖矩阵数字与实际题数一致
- [ ] 排版：标题与正文之间空一行；全文无 `---`/`***`/`___` 分割线（frontmatter 分隔符除外）
- [ ] 所有文件写入前已 Explain-first 确认；已有文件已备份
- [ ] 答案册由脚本生成且与习题 callout 一致
